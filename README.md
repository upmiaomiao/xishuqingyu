# 西书清语（xishuqingyu）

环评业务的四件套：**法规问答（RAG）＋ 报告智能审核 ＋ 报告自动生成 ＋ 知识图谱**，
跑在一台内网服务器（`10.201.31.10`）的 `:8011` 上。

本仓库是这套系统的**全部前后端代码**（不含语料、向量索引、PDF 与模型权重）。

## 目录结构

```

  home/test/
    xishu_qingyu_serve/     8011 站点

        data/question-bank.json  示例题库（焚烧 32 条 / 固废 39 条，见「示例题库」一节）
                                 **只在线上，不入库** —— 客户评测题原文，理由见「不入库的东西」
      xishu_pipeline/       后端管线（FastAPI 路由 + 检索 + 图谱 + 审核/生成对接）
      kg_data/              知识图谱数据 graph_full.json
      tests/                前端挂载自检 ＋ 题库面板行为测试（后者需本机 Node ≥ 14）
      launch_*.sh           启动脚本（问答 8011、bge-m3 向量 34004、bge-rerank 34005）
    fagui_serve/            法规问答代理 + 启动脚本

    eia_audit/              智能审核引擎：audit/ ＋ 入口与自检脚本

    fagui_rag/              法规 RAG：建索引/检索脚本 ＋ criteria/（JSON 判据）
ops/                        运维与测试脚本（部署、勘察、验收、回归），线上平铺在 /home/test
ops/历史脚本/                历次勘察/修复/验收的一次性脚本（原「站点全量测试」那一批）
```

`server/` 之所以按线上路径摆，是为了**重新部署时不用猜文件该放哪**：

```bash
cp -r server/home/test/* /home/test/
cp -r server/data/*      /data/
```

## 四块东西分别是什么

| 模块 | 线上位置 | 说明 |
|---|---|---|
| 8011 站点 | `/home/test/xishu_qingyu_serve` | 前端四个页面 + FastAPI 管线；**重启只走** `bash /home/test/安全重启8011.sh` |
| 法规 RAG | `/data/fagui_rag` | 语料 `okf_bundles/`（4 千余份 md）→ 向量索引 `index/`（30 余万块）；`criteria/` 放审核/生成共用的 JSON 判据 |
| 智能审核 | `/data/eia_audit` | 18 项基础判据 + 专项判据，输出「问题 / 需人工确认 / 判据轨迹」三件套 |
| 报告生成 | `/data/eia_report_gen` | 填报 → 判定（名录/标准/风险）→ 叙述（带出处闸门）→ docx 成文 |

## 关键设计（几个容易踩的点）

- **不编造**：法规问答只答库里有出处的；报告生成写不出出处的事实就不写，措施名在事实表里找不到的整句剔除。
- **现行性**：引用标准是否被替代，查 `criteria/标准现行性.json`；表里没有的一律**不下断言**，只报「未核实 / 需人工核对」。
- **单位**：审核侧面积统一按 ㎡ 折算（1 亩 = 2000/3 ㎡）；生成侧用量统一折算成「吨」（万吨、kg、千克都认）。
- **缺失就标缺失**：必填而未填的（如最大贮存量）显式写「未给…须人工核定」，不替用户补数。

## 示例题库（问答页输入框上方那条）

用户在输入框上方点「示例题库」就地展开面板，两级分类：**垃圾焚烧**（项目准入与环保合规 16 /
技术路线与方案编制 5 / 现场运行与异常处置 2 / 趋势复盘与数据沟通 9）与**固废**（专业展示案例
简单 5 / 中等 3 / 困难 11 / 日常问题展示 20），共 **71 条**。点条目 = 把该条全文填进输入框并直接
发送；点「全文」只展开，不发送。

数据只有一处：`frontend/data/question-bank.json`（**增删题目只改这个文件**，不碰代码）。
注意这个 JSON **只在线上、不入库**（客户评测题原文，理由见「不入库的东西」），改完不用重启 8011。
出题时定下的几条规矩：

- **只放题干**。原始题集里的 `来源：训练集 sft3_accepted`、`效果证据：v5 焚烧测试 heldout_03/04`、
  judge 五维、工艺域这些是**内部评测口径**，一律不进给客户看的 JSON（`ops/查题库契约.py` 会拦）。
- **去重**：固废"困难"里 `#6` 与焚烧/项目准入 `#5` 是同一道（飞灰取样器专利题，保留焚烧那份）、
  `#12` 与固废 `#5` 完全重复 → 各删一条（故困难 13→11）。固废 `#13` 与 `#5` 是同一个铝压铸案子的
  停产情形，**相似度 0.644，算两道题，保留**。
- **英文题译成中文**：焚烧「现场运行与异常处置」那 2 条原文是英文（`You are the on-duty engineer…`），
  界面只显示中文，PDF 原文不进仓库。
- 段落里出现的编号列表（如固废困难 `#9` 正文里的「2. 该公司在检验过程中…」）**不是**新题目，
  解析时按小节区分处理，别当成切分点。

## 改动纪律

线上是生产环境，本项目一直按这套流程改：

1. 改前 `md5sum` 核对目标文件；
2. 备份 `*.bak_before_<事项>_<时间戳>`；
3. 本地跑单测 → 上传 → 线上跑既有套件回归；
4. **真机样例验证**（拿真实填报/报告跑一遍，看实际输出）；
5. 记档（改动、md5、回滚命令、验证结论）。
6. `python tools/同步线上到仓库.py --apply --commit --push` 把改动回流进仓库（见下一节）。

## 线上改了，怎么同步回仓库

线上（`/home/test`、`/data/*`）才是运行的那份，仓库是它的镜像。改完线上代码后**别手工 cp**，
用同步工具：

```bash
# 1) 只看差异（默认，不动任何文件，有差异时退出码 1）
python tools/同步线上到仓库.py

# 2) 取回并落地（改动的旧文件先备份到 _同步/已删除备份/）
python tools/同步线上到仓库.py --apply

# 3) 落地 + 提交 + 推送
python tools/同步线上到仓库.py --apply --commit --push
```

它做的事：把 `tools/_服务器侧_清单与md5.py` 上传到线上 → 逐文件算 md5（同时算一份「去掉 CR 后」
的 md5，用来识别只差行尾的情况）→ 与仓库 `git ls-files` 比对 → 差异分类报出 → `--apply` 时按清单
打包取回、**逐个核对 md5 一致后**才写进仓库 → 线上已删除的文件先移到 `_同步/已删除备份/<时间戳>/`。

判定口径：

| 情况 | 处理 |
|---|---|
| 内容不同 | 更新（`--apply` 时取回） |
| 线上新增 | 取回并新增 |
| 线上删除 | 从仓库移除，先备份到 `_同步/已删除备份/` |
| 仅行尾不同（CRLF ↔ LF） | 忽略 —— 仓库按 `.gitattributes` 统一存 LF，不报假更新 |
| `ops/` 里线上没有同名的 | 只提示、**不删**（那是仓库独有的本地工具，如 `搭git仓库.py`） |

不参与同步（仓库独有）：`tests/`、`tools/`、`ops/历史脚本/`、`ops/工作区脚本/`、仓库根文件。

编码（踩过一次，别再踩）：helper 是本机 Python，stdout 接到管道时按**控制台编码**（中文 Windows = cp936）
输出，而工具按 UTF-8 读 —— 中文路径会变成替换字符 `U+FFFD`，比对结果**看着正常其实全是假的**
（2026-09-24 真机报出"线上新增 295 个"，实际一个都没变）。现在两头都堵住了：给子进程强制
`PYTHONUTF8=1`，解码按「UTF-8 严格解 → 退回本地编码」；万一清单里仍出现 `U+FFFD`，工具**直接中止**
而不是接着比对。自测里有这条回归断言。

依赖：同步工具复用工作区的 SSH helper（`服务器会话/put_file.py`、`runcmd.py`、`get_file.py`，
凭据读 `账号.md`）。默认在 `../服务器会话` 找，路径不同就加 `--helpers 目录`。
自测（不连服务器，用合成清单验证比对逻辑）：`python tools/自测_同步工具.py`。
推送前自检（含全部历史，第 ③ 层会用 `账号.md` 里的真实口令原文去搜，只报长度不打印口令）：
`python tools/查敏感信息.py`。

两个提醒：同步只搬代码、**不替你跑测试**（先按上面的「改动纪律」验完再同步）；
`--commit` 若发现工作区有与本次同步无关的改动会拒绝自动提交，避免把别的改动裹进来。

## 不入库的东西

语料（`okf_bundles/`、`eia_reports_raw/`、`guides_pdf/`）、向量索引本体（`index/` 及其备份里的向量文件）、
审核/生成结果与缓存、`*.bak_*` 备份、`.env`、日志与 pid。这些都在服务器上，体积合计约 20 GB。

**例外**：每份索引的 `meta.json`（构建溯源：构建时间、源索引、块数、嵌入配方）**入库**，
路径保持与线上一致 —— `server/data/fagui_rag/index*/meta.json`。索引本体不入库，别把 meta 拷回线上覆盖。

**另一类不入库**：`frontend/data/question-bank.json`（示例题库，71 道客户评测题原文）。它不是"太大"
或"临时"，而是**有意不公开** —— 题集是客户拿来评测模型的资产，本仓库是公开的，推上去 git 历史
就撤不回来。配套的三处防线：`.gitignore` 忽略了它、同步工具的 `tools/_服务器侧_清单与md5.py`
里 `SKIP_REL` 按路径排除它（否则每次同步都会报"线上新增"）、`tools/自测_同步工具.py` 有一条绊线
盯着这个排除规则（含反向对照）。要改题库就直接在服务器上改那个 JSON，改完**不用重启** 8011。
